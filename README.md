# Barbershop Booking Bot

Telegram Web App для записи в барбершоп: выбор мастера, услуги, даты и времени — прямо внутри Telegram, без сторонних сайтов и приложений. Запись подтверждает администратор, у него есть отдельная панель управления через бота (подтверждение записей, PDF-отчёты, добавление мастеров/услуг).

## Что это

Клиент открывает бота в Telegram, нажимает "📅 Записаться" и внутри мессенджера — без перехода на сайт — проходит весь путь записи: мастер → услуга → дата/время → контакты → подтверждение. Заявка уходит администратору на подтверждение; клиент получает результат (подтверждение или отказ с причиной) тем же чатом.

Интерфейс полностью двуязычный (русский / туркменский) — включая имена мастеров, названия услуг и текст уведомлений. Номер телефона — в туркменском формате (`+993XXXXXXXX`, префикс подставляется автоматически).

## Как устроена запись — жизненный цикл брони

```
Клиент отправляет заявку через Web App
            │
            ▼
      статус: pending  ──────────────┐
            │                        │  прошёл 1 час без ответа
   админ нажимает кнопку             │  (фоновая задача)
            │                        ▼
   ┌────────┴────────┐        статус: expired
   ▼                 ▼         клиенту — отказ с причиной
confirmed          rejected    "не подтверждено за час"
клиенту — ✅       клиенту — ❌ с причиной,
подтверждение      которую вводит админ текстом
```

Пока заявка `pending`, слот удерживается за клиентом (никто другой не может его забронировать). Подтверждённую запись клиент может отменить сам в любой момент через "📋 Мои записи" — слот сразу освобождается, админ получает уведомление об отмене.

## Функционал

### Для клиента
- Пошаговая запись в Web App: мастер → услуга → дата/время → имя/телефон → подтверждение
- Выбор языка интерфейса (RU/TK), сохраняется между визитами
- `/my` или кнопка "📋 Мои записи" — список активных записей с возможностью отмены
- Уведомления о подтверждении/отказе — на языке, который выбрал клиент

### Для администратора
- Уведомление о каждой новой заявке с кнопками **✅ Подтвердить / ❌ Отклонить** прямо в чате
- При отклонении бот спрашивает причину текстом — она уходит клиенту
- `/report [дата]` или кнопка "📊 Отчёт за сегодня" — PDF-таблица записей за день (кириллица поддерживается)
- **➕ Добавить мастера** / **➕ Добавить услугу** — бот пошагово спрашивает данные (включая название на двух языках) и сразу заносит в базу, без ручного доступа к БД
- Всё управление — постоянная клавиатура-меню в боте, ничего не нужно печатать вручную

## Стабильность и надёжность

Проект не просто демо — он выдерживает длительную работу без ручного вмешательства:

| Проблема | Решение |
|---|---|
| Расписание слотов физически кончается через N дней | Фоновая задача каждые 5 минут докатывает расписание на 14 дней вперёд для каждого мастера — бесконечно, без перезапуска |
| Заявка зависает без ответа администратора | Автоматический отказ клиенту через 1 час с объяснением причины, слот освобождается |
| БД растёт бесконечно | Записи и слоты старше 1 года автоматически удаляются той же фоновой задачей |
| SQLite не проверяет внешние ключи по умолчанию | `PRAGMA foreign_keys=ON` включается на каждом подключении |
| Гонки при параллельных запросах на один слот | `PRAGMA journal_mode=WAL` + уникальный constraint на `slot_id` в брони, конфликт ловится и возвращает понятную ошибку клиенту |
| Ошибка Telegram API при отправке уведомления роняла бы всю операцию | Уведомления — best-effort: ошибка логируется, но бронирование в БД уже сохранено и не откатывается |
| Необработанное исключение могло бы отдать клиенту стектрейс | Глобальный обработчик в FastAPI логирует полную ошибку на сервере, клиенту — только `{"detail": "Internal server error"}` |
| Контейнер падает — сервис недоступен | `restart: unless-stopped` + Docker healthcheck на backend; bot стартует только когда backend реально готов (`condition: service_healthy`) |
| Compromise одного контейнера = root на хосте | Оба контейнера работают от непривилегированного пользователя (`USER appuser`) |
| Bind-mount тома на Windows не держит Unix-права | БД хранится в именованном Docker volume — переносимо и корректно работает под любой ОС |
| Telegram кэширует Web App на своей стороне, после деплоя может показать старую версию | К ссылке Web App добавляется версия-таймстемп при каждом старте бота — Telegram всегда считает её новым ресурсом |
| `.env` / логи могли попасть в git или в Docker-контекст сборки | `.gitignore` и `.dockerignore` явно их исключают |

## Архитектура

```
Telegram-клиент
      │
      ├── aiogram-бот (bot/) ── постоянное меню-клавиатура, FSM-диалоги (отказ,
      │                          добавление мастера/услуги), коллбэки подтверждения
      │
      └── Web App (webapp/) ── статический HTML/CSS/JS, открывается внутри Telegram
                │
                ▼
        FastAPI backend (backend/)
                │
                ├── /api/*         защищено проверкой initData (клиент)
                ├── /api/admin/*   защищено внутренним токеном (действия админа)
                ├── /api/internal/* защищено внутренним токеном (действия клиента от имени бота)
                │
                ├── SQLite (WAL, внешние ключи) — мастера, услуги, слоты, записи
                ├── фоновая задача: автоотказ через час + очистка данных старше года
                └── уведомления клиенту и админу через Telegram Bot API
```

Bot и backend общаются напрямую по внутренней Docker-сети через отдельный секрет (`INTERNAL_API_TOKEN`) — это не пересекается с проверкой `initData`, которая защищает только публичный Web App API.

## Безопасность

Ключевое требование проекта — ни одна запись не попадает в БД без проверки, что запрос действительно пришёл из Telegram-клиента этого бота:

1. Telegram подписывает `initData` (данные о пользователе) собственным HMAC-SHA256, используя токен бота как секрет
2. Backend на каждый защищённый запрос пересчитывает подпись из `X-Telegram-Init-Data` заголовка тем же алгоритмом и сверяет её через `hmac.compare_digest` (защита от timing-атак)
3. Проверяется `auth_date`, чтобы отклонять устаревшие (перехваченные) данные
4. Все входящие данные валидируются Pydantic-схемами (формат телефона, длина имени, диапазоны id)
5. Двойное бронирование одного слота исключено на уровне БД (`unique` constraint + перехват `IntegrityError`)
6. Административные и служебные эндпоинты (`/api/admin/*`, `/api/internal/*`) защищены отдельным секретом, известным только backend и bot внутри Docker-сети — снаружи недоступны без него

Подробности реализации — в [backend/security.py](backend/security.py).

## Стек

- **Backend**: FastAPI, SQLModel (SQLAlchemy + Pydantic), SQLite, ReportLab (PDF)
- **Bot**: Aiogram 3.x (polling), FSM для многошаговых диалогов
- **Frontend**: Vanilla HTML/CSS/JS, Telegram Web App JS SDK
- **Инфраструктура**: Docker, Docker Compose, healthcheck, non-root контейнеры, именованный volume

## Запуск локально

Требуется Docker Desktop и туннель до `localhost:8000` с HTTPS (Telegram Web App не открывается по HTTP) — например [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/):

```bash
cloudflared tunnel --url http://localhost:8000
```

1. Скопируй `.env.example` в `.env`, впиши:
   - `BOT_TOKEN` — от [@BotFather](https://t.me/BotFather)
   - `WEBAPP_URL` — ссылка из туннеля
   - `ADMIN_IDS` — твой Telegram id (узнать можно у [@userinfobot](https://t.me/userinfobot))
   - `INTERNAL_API_TOKEN` — случайная строка, например `python -c "import secrets; print(secrets.token_urlsafe(32))"`
2. Запусти:
   ```bash
   docker compose up -d --build
   ```
3. Открой бота в Telegram, нажми `/start`

⚠️ Ссылка `cloudflared` временная и меняется при каждом перезапуске — для постоянной работы нужен собственный домен (см. чеклист ниже).

## Структура проекта

```
backend/
  main.py             точка входа, healthcheck, фоновая задача обслуживания, статика webapp/
  security.py          проверка HMAC-подписи Telegram initData + внутреннего токена
  routers.py            /api/masters, /api/services, /api/slots, /api/booking
  admin_routers.py       /api/admin/* — подтверждение/отклонение записей, PDF-отчёт, добавление мастера/услуги
  internal_routers.py     /api/internal/* — список записей клиента и их отмена
  models.py              таблицы SQLModel (Master, Service, Slot, Booking)
  schemas.py               Pydantic-валидация входящих данных
  notify.py                 уведомления клиенту/админу через Telegram Bot API (RU/TK)
  report.py                  генерация PDF-отчёта (ReportLab + кириллический шрифт)
  tasks.py                    автоотказ зависших заявок + очистка данных старше года
  seed.py                      демо-данные + автогенерация расписания на 14 дней вперёд
bot/
  main.py             /start, постоянное меню-клавиатура, FSM-диалоги, коллбэки
webapp/                Web App: index.html / style.css / app.js (i18n RU/TK)
docker-compose.yml
```

## Продакшен-чеклист

Для локальной демонстрации проект полностью рабочий, протестирован и устойчив к длительной работе (см. раздел выше). Что дополнительно нужно для реального сервера:

- [ ] Постоянный домен + HTTPS вместо временного `cloudflared`-туннеля
- [ ] Регулярный бэкап Docker volume с SQLite (данные больше не хранятся вечно, но бэкап всё равно нужен на случай сбоя сервера)
- [ ] Ограничение размера логов Docker (`max-size`/`max-file`)
- [ ] Reverse-proxy перед портом 8000, если сервис публикуется напрямую в интернет
